# 검증 결과와 남은 항목

**현재 후보의 로컬 검증 완료와 이전 기준본의 실보드 부팅 성공은 서로 다른 근거다.**
SD4 후보는 `variants/sd4-dma/`, 이전 기준본은 저장소 루트다.
이번 문서 갱신에서는 RTL·드라이버·이미지를 변경하거나 보드 시험을 새로 수행하지 않았다.

## 2026-11-10 SD4·DMA 후보

아래 근거 경로는 모두 `variants/sd4-dma/` 기준이다.

이미지 적재 시험은 CPU에서 Linux를 실행하지 않으며 DDR 초기 지우기 길이를 4096바이트로 줄인 시험이다.
CPU 저장소 시험은 펌웨어가 MMIO를 제어하는 시험이며 Linux MMC/DMAengine 드라이버 실행 시험은 아니다.
QEMU에는 새 SD 하드웨어 모델이 없어 복구 셸 경로로 검사했다. QEMU 결과는 MMC/ext4 런타임 성공 근거가 아니다.
Verilator의 카드·DDR 모델은 실제 카드, MIG PHY, DDR calibration, PCB 신호 품질을 검증하지 않는다.

### 배선 후 리소스와 타이밍

| 항목 | SD4 후보 최종 결과 |
|---|---:|
| 부품 | xc7a200tfbg484-2 |
| CPU / fabric / SD 최대 | 50 / 100 / 25 MHz |
| pixel / serializer | 74.25 / 371.25 MHz |
| LUT / FF / BRAM / DSP | 114,075 / 74,189 / 101.5 / 62 |
| 점유 Slice | 32,792 / 33,450 (98.03%) |
| WNS / TNS | +0.034ns / 0ns |
| WHS / THS | +0.027ns / 0ns |
| 배선 대상 net / 배선 오류 | 168,973 / 0 |

MIG·HDMI와 새 SD·DMA를 포함한 전체 보드 결과다. CPU/fabric setup uncertainty 0.300ns를 유지했다.
전체 최악 경로는 boot 상태→SD 버퍼 선택·CRC 관련 논리→SD DAT 출력 레지스터이며,
100MHz에서 데이터 지연 8.989ns 중 7.445ns가 배선이다. 물리 최적화로 -0.185ns에서 +0.034ns가 됐다.
CPU 내부 최악 경로는 LSQ RAM→LSU 주소 변환 레지스터, slack +0.646ns다.
작은 slack과 높은 Slice 점유율 때문에 후속 변경에는 전체 구현을 다시 검증해야 한다. CPU 100MHz 달성 결과는 아니다.

### DRC·CDC·외부 핀 범위

최종 DRC Error/Critical은 0, 기존 생성 MIG 내부 BUFC-1 4건과 REQP-1709 1건은 남아 있다.
CDC Warning/Critical은 0, Info는 CDC-3 19건과 CDC-9 18건이다.
Gray pointer 68비트의 제약·동기화 속성과 bus skew도 통과했다.
재사용 배치 도중의 부분 배선 리포트에 있는 PDIL/RTSTAT 항목은 최종 DRC에 남지 않았다.

원본 도구 로그의 Project 1-1108 Critical Warning 1건은 실행 속도를 위해 사용자 uncertainty를 무시하라는 제안이다.
그 제안은 적용하지 않았다. **원본 로그 전체의 Critical Warning이 0이라고 보고하지 않는다.**

SD 입력 5개는 ILOGIC에 배치됐다. 최악 입력 setup/hold는 +7.901ns/+11.973ns,
출력 setup/hold는 +11.344ns/+13.091ns다. 이는 설정한 카드/PCB 지연 예산에 대한 결과다.
DDR reset과 HDMI 양극 clock/data 출력 4개에는 외부 output-delay 예산이 지정되지 않았다.
비동기 UART·SPI MISO·I2C 입력 7개는 동기화기까지 최대 지연을 제한한다.
`evidence/board/io_timing_coverage.rpt`에 범위를 보존했다. 모든 외부 수신기 전기 조건을 검증했다는 뜻은 아니다.

### 아직 남은 검증과 기능

- 새 이미지의 실보드 MMC 탐색, ext4 `/data` 마운트·쓰기·캐시를 비운 재읽기·재부팅 후 보존.
- 새 Linux MMC/DMAengine 드라이버의 실제 보드 실행, 카드·PCB 타이밍 및 실측 속도.
- 전체 CPU RTL에서 이번 SD 이미지로 Linux UART 셸까지 이어지는 콜드 부팅.
- 새 후보에서의 HDMI 화면·BoAYO 실행·WASD·BOSIO 구동 통합 확인.
- 전체 1GiB RAM 전수 검사 및 다른 PC에서의 바이너리 동일 재현.
- SD 연속 다중 블록 명령, BoAYO 렌더링 DMA 가속은 미구현. 기존 raw 부트 로더도 새 DMA로 대체하지 않았다.

## 2026-11-08 실보드 기준본의 기록

아래는 루트 기준본의 과거 결과다. 새 후보의 실보드 결과로 재사용하지 않는다.

| 항목 | 기존 근거 |

과거 스냅샷 이후 2억 사이클 시험은 셸 이전에 제한에 도달했다. 이를 현재 실행 중인 작업으로 표기하지 않는다.

## 이번 문서 게시 검사

`python scripts/verify_sources.py`와 `python scripts/verify_sd4_publication.py`로 각각 기준본과 후보를 확인한다.
문서 링크·게시 파일 해시를 갱신하고, 검증 코드 234개 및 기존 기준본 입력 125개의 해시는 유지한다.
문서 변경만을 이유로 장시간 RTL·합성·배선을 재실행하지 않는다. 검증 근거의 실행 시점은 원본 로그를 따른다.
