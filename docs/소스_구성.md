# 소스 구성과 기준 버전

## 두 구성의 위치

| 구성 | 프로젝트 루트 | 소스·산출물 기준 |
|---|---|---|
| 현재 SD4·DMA 후보, 2026-11-10 | `variants/sd4-dma/` | 검증 소스 234개와 해당 전체 보드 구현·이미지 해시 |
| 실보드 부팅 기준본, 2026-11-08 | 저장소 루트 | 기존 보드 입력 125개와 trace-v2 이미지 |

SD4 후보는 로컬 `work/sd4-dma`를 게시한 것이다. 이전 루트는 `work/bosio-clocksource-fix`의 실보드 검증본이다.
두 구성은 각각 자신의 `soc/bosio_sources.f`를 사용한다. 같은 파일명이라도 경로를 섞지 않는다.
독립 스케줄러 저장소 `VARZero/ORYUKDO`와 이 SoC 저장소도 구분한다.

루트의 `provenance/package_files.json`은 최초 게시 시점의 기록이다. 최신 문서 전체의 해시 목록이 아니다.
기준본은 `scripts/verify_sources.py`, 후보는 `scripts/verify_sd4_publication.py`로 확인한다.

## SD4 후보의 파일

아래 경로는 모두 `variants/sd4-dma/` 기준이다.

| 경로 | 내용 |
|---|---|
| `rtl/`, `gen2/`, `soc/rtl/` | 스케줄러·CPU·EX·CSR·MMU/TLB |
| `soc/bosio/or_sd_native.sv` | native SD 명령·데이터·CRC·타임아웃 |
| `soc/bosio/or_sd_storage.sv` | 부팅/런타임 소유권과 SD/DMA 연결 |
| `soc/bosio/or_storage_dma.sv` | SD 전송·DDR 복사/채우기 |
| `soc/bosio/or_storage_plic.sv` | M/S context, 우선순위·claim/complete |
| `soc/board/` | 보드 최상위·MIG bridge·SD 핀 제약·Vivado 스크립트 |
| `software/storage/oryukdo_sd.c`, `oryukdo_dma.c` | Linux MMC / DMAengine 드라이버 |
| `software/storage/linux.config` | 이번 커널의 실제 설정 |
| `software/bosio/` | 보존한 ABI 3 제어 엔진·드라이버·도구와 새 장치 트리 |
| `validation/`, `evidence/board/` | 기능 시험·이미지·합성·배선 원본 근거 |
| `provenance/source_sha256.json` | 게시 시 대조한 검증 코드 234개의 해시 |
| `provenance/publication_files.json` | 후보 문서·증거를 포함한 현재 게시 파일 해시 |
| `provenance/board_manifest.json`, `release_assets.json` | 구현 결과·비트스트림·이미지와 공개 첨부파일 해시 |

스케줄러 알고리즘과 공식 MIG·HDMI IP 본문은 유지했다. 5-master 중재와 외부 인터럽트 연결을 추가했고,
보드 bridge의 RAM 목적지 고정값 문제를 수정했다. 자세한 변경은 [상세 문서](../variants/sd4-dma/README_STORAGE_KO.md)에 있다.

## 현재 Linux 전체 소스와 userspace

Linux 버전은 6.12다. 이번 실제 커널 빌드의 전체 소스는
[SD4 사전 릴리스](https://github.com/VARZero/ORYUKDO-3d5i_BOSIO_SoC/releases/tag/sd4-dma-20261110-candidate)의
`linux-6.12-sd4-dma-source.tar.gz`이며 SHA-256은 다음과 같다.

`62a15cf984f1f9100cfa2a7f986f2954195d7334c8eb29a0c5e2553f4a9288d3`

압축본의 새 MMC/DMA 드라이버와 Git의 원문이 일치한다. 새 호스트·DMA·PLIC·BLOCK·MMC_BLOCK·EXT4 설정,
`software/bosio/gen3-bosio.dts`, `/data` 초기화와 `storage-check`가 이번 이미지에 반영됐다.
루트 파일시스템은 initramfs이며 BusyBox와 BoAYO native-v2 실행 파일을 해시로 대조해 보존했다.
그 기록은 `provenance/preserved_userspace.json`에 있다. Bash/Vim 추가나 BoAYO DMA 가속을 수행한 버전은 아니다.

후보의 `software/linux/`에는 상속된 trace-v2 진단 자료가 남아 있다. **그 디렉터리의 3개 패치나
`scripts/prepare_linux.py`만으로 현재 SD4 커널 소스를 복원했다고 간주하면 안 된다.**
현재 소스는 위 전체 압축본, 현재 설정은 `software/storage/linux.config`를 기준으로 한다.
빌드 스크립트의 로컬 userspace·BoAYO 도구·설치 경로 의존성은 [빌드 문서](빌드.md)에 구분했다.

## 2026-11-08 trace-v2 기준 자료

아래는 저장소 루트에 보존한 이전 기준본의 설명이며 SD4 후보 전체의 변경 개수가 아니다.

Linux 6.12 원본 압축 파일 해시는 `b1a2562be56e42afb3f8489d4c2a7ac472ac23098f1ef1c1e40da601f54625eb`다.
당시 일반 파일 86,618개를 비교했고 변경은 `kernel/time/clocksource.c`, `timekeeping.c`,
`tick-common.c`의 진단 표시 3개였으며 추가 파일은 없었다.
루트 `software/linux/modified/`, `patches/`, `config`, `initramfs.original.list`는 그 기준본의 자료다.
`scripts/prepare_linux.py`는 그 원본과 패치를 복원한다.

OpenSBI v1.8.1의 기존 generic RV32 `fw_jump.bin`을 사용한다.
기준 커밋은 `74434f255873d74e56cc50aa762d1caf24c099f8`이다.
기존 userspace는 BusyBox 1.37.0, musl 1.2.5, RV32 ILP32 정적 실행 파일이다.
루트 `provenance/trace_v2_image.json`은 이전 SD의 페이로드 근거이며 새 이미지 근거로 쓰지 않는다.
`firmware_origin.json`도 이전 출처 기록이다. 진단 출력이 있는 부팅 시간은 일반 커널 성능 기준이 아니다.

## 외부 IP와 게시 범위

MIG는 `mig_a.prj`와 생성 Tcl을 제공하고 설치된 Vivado 2022.2에서 MIG 4.2와 XPM을 생성·참조한다.
생성 IP·대형 DCP·Vivado 설치 파일은 Git에 넣지 않았다. 공식 Digilent HDMI 원문·해시·라이선스를 보존했다.

Git에는 코드·문서·검증 로그·리포트를, 릴리스에는 `.bit`, `.img`, RTL 및 Linux 전체 압축본을 둔다.
릴리스는 고정된 검증 시점의 산출물이고 `main`의 문서는 이후에도 갱신될 수 있다.
문서 수정으로 기존 릴리스 태그나 바이너리 해시를 변경하지 않는다.
원본 보고서의 로컬 경로는 당시 실행 근거로 보존한다. 개인 접속 도구·보드 PDF·인증 정보는 게시하지 않는다.
