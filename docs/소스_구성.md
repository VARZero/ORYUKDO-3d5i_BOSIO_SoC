# 소스 구성과 기준 버전

## 하드웨어

기준 작업본은 `work/bosio-clocksource-fix`이다. Vivado의 최종 TLB 보드 빌드가 남긴 입력 해시와 비교하여 저장소 안에 들어오는 125개 입력의 원문이 같은지 확인했다. `provenance/board_sources.json`이 기준이며 `scripts/verify_sources.py`로 재검사할 수 있다.

기존 `VARZero/ORYUKDO` 저장소는 독립 스케줄러용이다. 이 저장소는 당시 보드에 적용한 스케줄러, CPU 실행기, 메모리·CSR, BOSIO 및 물리 보드 연결을 함께 포함한다. RTL 변경 없이 경로를 유지하여 `soc/bosio_sources.f`로 컴파일한다.

외부 AMD MIG는 원본 생성 파일 전체를 복사하지 않고 `mig_a.prj`와 생성 Tcl을 제공한다. Vivado 2022.2가 MIG 4.2와 XPM을 생성·제공한다. 당시 사용한 XCI의 해시는 별도 외부 입력으로 기록했다. 공식 Digilent HDMI IP 원문과 원본 해시, 라이선스는 포함한다.

## Linux

원본은 Linux **6.12**, 원본 압축 파일 SHA256은 다음과 같다.

`b1a2562be56e42afb3f8489d4c2a7ac472ac23098f1ef1c1e40da601f54625eb`

실제 진단 커널 소스의 일반 파일 **86,618개**를 원본 압축본과 비교했다. 추가 파일은 없으며 차이는 다음 세 파일의 진단 출력뿐이다.

| 파일 | 변경 |
|---|---|
| `kernel/time/clocksource.c` | C0..C4 초기화 진행 표시 |
| `kernel/time/timekeeping.c` | N0/N1, X0..X5 시계 전환 진행 표시 |
| `kernel/time/tick-common.c` | T0/T1 진입·복귀, TL catch-up 반복 표시 |

`software/linux/modified/`에는 세 파일의 전체 소스를, `patches/`에는 원본에 적용할 패치를 보존했다. `config`는 실제 진단 커널의 설정이다. `initramfs.original.list`의 절대 경로는 당시 빌드 이력이며, 새 빌드 스크립트는 현재 경로로 별도 목록을 생성한다.

전체 소스 압축본 `artifacts/linux-6.12-oryukdo-trace-v2.tar.gz`도 준비했다. Git 저장소에는 거대한 원본 트리를 중복 저장하지 않고 원본 버전·해시·패치·복원 도구를 넣는다. 전체 압축본은 GitHub Release 첨부용이다. `scripts/prepare_linux.py`로 복원하는 내용과 같은 소스다.

타이머 정지 개선의 기능 수정은 CPU TLB에 있다. Linux의 HZ를 낮추거나 타이머를 끄는 변경은 없다. 진단 출력은 실행 시간을 바꾸므로 진단 커널의 부팅 시간은 성능 기준으로 쓰지 않는다.

## 부팅 소프트웨어

- OpenSBI v1.8.1, 커밋 `74434f255873d74e56cc50aa762d1caf24c099f8`, 기존 generic RV32 `fw_jump.bin`.
- BusyBox 1.37.0, musl 1.2.5, RV32 ILP32 정적 실행 파일.
- `software/userspace/init.c`: 콘솔과 기본 파일시스템, BusyBox 쉘 시작.
- `software/userspace/ddrcheck.c`: 상위 물리 메모리 페이지 읽기·쓰기 확인.
- `software/firmware/gen3.dts`: 실제 trace-v2 부팅 인자와 메모리 예약.

펌웨어 Image와 WSL 진단 빌드 Image의 바이트 일치를 확인했다. SD에 들어간 OpenSBI·Image·DTB와의 대응은 `provenance/trace_v2_image.json` 및 이미지 검사로 확인한다. `provenance/firmware_origin.json`은 이전 일반 커널의 출처 기록이므로 현재 Image의 해시 기준으로 사용하지 않는다.

## 게시 범위

자동 완료 감시 프로그램, 개인 UART 세션 제어, 과거 실패 빌드, 보드 PDF, Vivado 설치 파일은 게시 패키지에 포함하지 않는다. 원본 UART와 보고서는 증거로 보존하므로 당시 로컬 경로가 남아 있을 수 있다. 그것들은 빌드에 필요한 경로가 아니다.
